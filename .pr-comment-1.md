**1. Which CUDA version trips the C1189.**
Failing combo here: CUDA 13.4 (nvcc V13.4.59, bundled CCCL 3.4.2) + MSVC 14.44.35207 (VS 2022 BuildTools) on Windows 11. The `#error` lives in the toolkit's own `cccl/cuda/std/__cccl/preprocessor.h` and fires on `_MSC_VER` with `_MSVC_TRADITIONAL == 1`. Note this diagnostic was promoted from a warning to a fatal error with the CUDA 13.2 CCCL — that's why 13.0.2 in CI passes: NVIDIA's own cuda-samples repo hit the same wall on 13.2 and added the identical `-Xcompiler=/Zc:preprocessor` ("previously a warning … now leads to a build error"). Done in 703e3301: `docs/platforms.md` now says CUDA 13.2+ needs the flag and points at it for anything building these headers outside this CMakeLists.

**2. Host `.cpp` files pulling CUDA headers.**
They build cleanly without the flag, empirically: ~50 `src/kernels/*_parity.cpp` files include `<cuda_fp16.h>`/`<cuda_runtime.h>`, and since the flag here only appends to `CMAKE_CUDA_FLAGS`, every host TU in the 194-target build was compiled with the traditional preprocessor, all green. Mechanically that makes sense: CUDA 13.4's `cuda_fp16.h` pulls in `vector_types.h`/`vector_functions.h` but not the `cuda/std` (CCCL) chain where the guard lives. The guard only triggers through `cuda::std`, which today is reached from `.cu` kernels (`dec_gdn_rec.cu`, `mid_chain.cu`). So no `/Zc:preprocessor` needed on the C/C++ side, and `/Zc:__cplusplus` stays as-is.

**3. `CMAKE_CXX_COMPILER_ID` vs the CUDA host compiler.**
Fair point — what actually needs the flag is `cl.exe` as *nvcc's host* in traditional mode. I had mirrored the existing `/Zc:__cplusplus` block's gate for consistency, and CCCL's own guard excludes clang (`#if defined(_MSC_VER) && !defined(__clang__)`), so a clang host is never the one complaining. Pushed as b50eb016, gated on the host compiler now:

```cmake
if(NOT CMAKE_CUDA_HOST_COMPILER OR CMAKE_CUDA_HOST_COMPILER MATCHES "(^|[/\\\\])cl(\.exe)?$")
  string(APPEND CMAKE_CUDA_FLAGS " -Xcompiler=/Zc:preprocessor")
endif()
```

Unset means nvcc's default Windows host, which is `cl.exe`; the leading separator keeps `clang-cl.exe` from matching the tail.
